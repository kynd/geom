# Content Audit — Plan & Findings

Reviewing all public pages against four criteria:

1. **Technical accuracy** — does the prose match what the demo code actually does?
2. **Structure** — high-level intro first, details pushed into subheads/`.page-note`/`<details>`?
3. **Common styles** — `.subhead`, `.page-note`, `.shape-desc`/`details` white labels, objective voice, footer, math formatting, per CLAUDE.md conventions
4. **Consistency** — same voice/vibe across pages (per `writing-style-guide.md`)

Status: audit complete, no edits made to page content.

## Priority findings (highest severity first)

1. **Sound analysis — Spectrograms section (major, technical).** The prose describes the "densest 60-second window" pipeline, but the displayed images are actually the full ~4-minute track (`public/sound/full/`, not `public/sound/highlights/`). The text describes a different image than what's on the page.
2. **Archive — SDF blend (major, technical).** Claims "only those two [assigned] stems are audible," but the demo only ever plays the master mix — there's no per-stem soloing. Off-nav (dev-only sketch), but wrong if anyone opens it.
3. **Parametric shapes — Saddle blend shape (major, technical).** The formula is missing a `0.72` scale factor present in the code, and separately claims "A=±2 rotates the axes 45°" which is a math error (correct value is 22.5°).
4. **Composition — missing Radar 3D section (moderate, technical).** The demo has a full scriptable "Radar 3D" panel (`panes_count` + 11 `radar_*` params) that isn't mentioned anywhere in the page's parameter list — looks like the prose wasn't updated after that feature shipped.
5. **Sound-reactive environment — two moderate factual errors:** Drifting caustic's "incommensurable, never repeats" claim is false (all 7 rates are integer multiples of 0.73, period ≈8.6s); Bilateral spectrogram's L/R channel-to-half mapping is stated backwards (also wrong in the demo's own in-app description, so it's a duplicated error, not just a doc bug).
6. **Effects and Refinements + Composition (moderate, structural/style).** Both pages use flat `<ul><li>` control lists directly in the page flow instead of the `.subhead`/`.page-note`/`<details>` pattern used everywhere else — the clearest structural and stylistic outlier on the site, and the biggest gap against the "push details into small/collapsible text" review criterion.
7. **Multitrack visualization — Track prominence intro paragraph (minor, structural).** 5 sentences in one paragraph, violates the style guide's own 4-sentence-per-paragraph rule; also still has one instructional-voice slip ("Toggle stems on and off") that survived the earlier site-wide cleanup pass.
8. **Composition's voice (minor, consistency).** Reads as pure reference documentation — jumps into parameter/UI enumeration without the "lead with why" framing used elsewhere (e.g. Sound analysis's Python-script paragraph).
9. **Transitions.astro — "Prism rainbow — new:" (minor, consistency).** Reads like a leftover dev/changelog note rather than finished copy.

Everything else below is lower-priority (minor omissions, cosmetic naming mismatches, one inline style attribute) — see full section-by-section notes.

## 1. Technical accuracy vs. demo code

### Sound analysis
- **Spectrograms section — MAJOR**: prose describes the "densest 60-second window" pipeline (`sound/trim_audio.py`, writes to `public/sound/highlights/`), but the `<img>` tags on the page actually point at `public/sound/full/${base}_L.png` — generated by `sound/generate_audio.py` from the **entire ~4-minute track** (confirmed 1443×128px ≈ 240s @ 10 frames/px, vs. the highlights images at 360×128px = exactly 60s). **The text describes a different image than the one displayed.** This needs fixing.
- Offline-analysis dB formula, STFT/roll-off/Mel-filterbank claims, byte format (258 floats/frame, 1032 bytes), and silent-lead-in skip logic: all verified accurate against `sound/process_audio.py` and `main.js`.

### Parametric shapes
- Sphere SDF, ray-marching mechanics, Platonic dual face/vertex/edge counts, scalar-field rendering (fixed-step + sign-change + binary search): all verified accurate.
- **Moving scalar fields shape index** — the list has exactly 20 entries matching the shader 1:1 in order (not 17 as originally estimated). Specific issues found:
  - **Saddle blend — MAJOR**: prose formula omits a `0.72` scale factor the code actually applies to the whole saddle expression.
  - **Saddle blend — MODERATE, math error**: prose claims "at A=±2 the axes have rotated 45°" — the correct rotation at A=2 (via tan(2θ)=A/(a−c)) is 22.5°, not 45°. This is a math error independent of the code.
  - **Tanglecube — minor**: code applies a hidden `1.18×` coordinate scale and `c(t) = 10.5 + 3.2 sin(0.45t)`, not reflected in the simplified prose formula.
  - **Traveling ripple, Wave sheet, Rippled cone, Bumpy sphere, Flipping paraboloid — minor, pervasive pattern**: every one of these has amplitude/frequency/phase constants rounded away in the prose (e.g. ripple is actually `0.52·e^(-1.1r)·cos(5.5r−2.2t)`, not `e^{-r}cos(5r-2t)`). Likely intentional simplification for readability, but every numeric coefficient across these 5 entries is inexact — worth a deliberate decision (state "simplified" or tighten the numbers).
  - **Naming mismatch — minor/cosmetic**: several prose names don't match the demo dropdown's actual labels (e.g. "Saddle blend" vs. dropdown's "Tilting saddle"; "Twisted torus" vs. "Rotating torus"; "Bumpy sphere" vs. "Rotating harmonic sphere") — a reader toggling the dropdown won't see matching names.
  - All other 14 entries (Rippling torus, Pulsing sphere, Oscillating saddle, Gyroid, Schwartz P, Lemniscate, Swaying ellipsoid, Chmutov T₄, Pulsing Gaussian, Schoen I-WP, Twisted torus, Wavy hyperboloid, Permuted cubic, Flipping paraboloid's mechanics) verified accurate or exactly matching coefficients.
- Scalar field blend formula: consistent with the shared scalar-marcher architecture, not independently flagged.

### Sound-reactive environment

Actually false — all seven rates are integer multiples of 0.73 (0.73, 1.46, 2.19, … 5.11), so the pattern is exactly periodic with period ≈8.6s. Should be corrected or the claim softened.

## 4. Voice/vibe consistency across pages

- **Sound analysis → Multitrack visualization**: all six of these pages share one clearly consistent voice — objective third-person description, "we" reserved for monologues, technical depth pushed into a demoted register, no instructional phrasing (with the one "Toggle stems" exception noted above). This is the site's dominant, well-established voice.
- **Effects and Refinements & Composition**: read like a different register — closer to software reference documentation (bulleted parameter lists, code identifiers, "new:" annotation) than the descriptive-explanatory voice used everywhere else. This is the clearest cross-page consistency gap on the site.
- **Home**: intentionally uses a more first-person, narrative "we talked about..." framing in the rules section — this reads as a deliberate distinct "narrator" voice for the site's front door versus the demo pages' objective voice, not an inconsistency, but worth confirming that's the intended split (home = narrative frame, content pages = objective documentation) rather than something that should also propagate.
- **Appendix**: neutral/reference tone, consistent with its role as a glossary; doesn't clash with anything since it doesn't share prose with demo pages.
